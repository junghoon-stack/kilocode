# 관리자 전용 Provider 자격 증명 운영 원칙

## 정책

QraftCode 사용자에게 자신의 Provider API 키를 넣으라고 요구하지 않습니다. QraftCode Zen 운영자가 자신의 Provider 계정으로 발급한 API 자격 증명을 서버에 설정하고 관리합니다. 제품 이용자는 QraftCode에 로그인해 사용 가능한 모델을 선택하며, Provider 키를 보거나 제출하지 않습니다.

## 현재 구현 상태

현재 QraftCode Zen에는 Provider 어댑터나 운영자 자격 증명 로더/저장소가 연결되어 있지 않습니다. 따라서 이 문서는 정책과 운영 설계이며, 키를 입력하는 관리자 UI나 실제 키 등록을 의미하지 않습니다. Provider 키를 채팅, 코드, 공개 저장소 또는 지금의 Web 미리보기에 입력하지 마세요.

## 운영자 설정 방식(기능 구현 후)

1. Provider 공식 문서에 따라 운영자가 Provider 계정에서 서버용 키를 발급합니다.
2. 프로덕션 환경의 Secret Manager(또는 이에 준하는 배포 플랫폼의 encrypted secret storage)에 관리자 권한으로 등록합니다.
3. Zen 서버의 검증된 Provider 어댑터만 해당 키를 읽게 합니다. 키는 브라우저, SDK 사용자 응답, 로그, 오류 메시지, analytics에 절대 전달하지 않습니다.
4. Provider가 문서화한 인증 변수 이름/형식을 사용합니다. Provider 확인 전에는 endpoint, 모델 ID, 인증 header, secret 이름을 추측하지 않습니다.
5. 키의 권한은 최소화하고, 사용량/비용 한도와 rate limit을 설정하며, 정기 교체 및 즉시 폐기 절차를 마련합니다.
6. 키 미설정/잘못된 키는 fail-closed 처리합니다. 사용자에게 필요한 안내는 “현재 Provider 이용 불가”로 제한하고 비밀 값이나 내부 오류를 노출하지 않습니다.

개발 단계에서 로컬 환경변수를 사용할 수 있게 될 경우에도 실제 키가 포함된 `.env` 파일은 버전 관리에 넣지 않습니다. 운영 배포는 TLS, 관리자 접근통제, 서버 측 암호화/Secret Manager, 로그 redaction, 사용량 제한 및 보안 검토를 완료하기 전에는 활성화하지 않습니다.

## 사용자 경험

- 사용자는 Provider 키를 입력하지 않습니다.
- UI는 Provider별 가용성, 모델, 기능 및 상태만 보여줍니다.
- Provider가 관리자 자격 증명이나 운영 설정 부족으로 비활성화된 경우 비활성/점검 중이라고 표시합니다.
- 가용성 상태는 실제 health check와 검증 결과에 기반해야 하며, 미검증 Provider를 사용 가능하다고 표시하지 않습니다.
- 외부 Provider가 요청/IP/메타데이터를 처리할 수 있음을 고지합니다. 완전한 익명성을 약속하지 않습니다.

## 보안 출시 기준

관리자 키 연결은 실제 어댑터와 공식 문서 검증, 비밀 값 접근 통제, 키 유출 방지 테스트, 로그 검사, key rotation/revocation 절차 및 provider별 실제 API 테스트를 통과해야 합니다. 그 전까지 QraftCode 제품에서 사용 가능한 API 키 등록 기능이 있다고 주장하지 않습니다.
