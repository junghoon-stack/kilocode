# QraftCode API 설정 UX 및 보안 요구사항

## 대화창과 제품 화면의 차이

ChatGPT 대화창 안에 실제 입력 필드가 있는 QraftCode 설정 모달을 띄우거나 API 키를 저장할 수는 없습니다. API 키를 이 대화에 붙여넣지 마세요. 대화는 비밀번호 관리자나 보안 자격 증명 저장소가 아닙니다.

QraftCode Web 제품에는 사용자가 직접 여는 **설정 → 모델 및 API** 화면을 만들 수 있습니다. 현재 Web 로그인, Zen의 인증/저장 API, 암호화된 자격 증명 저장소가 구현되지 않았으므로 이 문서는 UX와 보안 설계이며, 현재 동작하는 API 키 저장 기능을 의미하지 않습니다.

## 권장 화면

설정 페이지에서 “모델 및 API” 탭을 선택하면 다음을 보여줍니다.

- Provider 선택 목록과 검증 상태
- 선택한 Provider의 문서 링크 및 요구 인증 방식
- API 키 입력란(기본 마스킹, 표시/숨기기 버튼)
- 선택 사항인 모델 ID와 사용자 지정 endpoint(해당 Provider가 공식 지원할 때만 표시)
- 연결 테스트 버튼(서버 측 안전한 테스트가 구현된 경우에만 활성화)
- 저장, 키 삭제, 마지막 확인 상태
- 데이터 흐름과 Provider의 요청 처리/보존 안내

입력창에는 실제 키 값을 기본값으로 다시 채우거나 응답 데이터로 반환하지 않습니다. 저장된 키는 “설정됨” 상태만 표시하고, 사용자가 명시적으로 교체하도록 합니다. API 키는 ChatGPT 대화, URL, 브라우저 콘솔, 분석 이벤트, 오류 메시지 또는 애플리케이션 로그에 입력하거나 기록하지 않습니다.

## 보안 경계와 출시 기준

- Zen에 저장하는 자격 증명은 서버 전용이어야 합니다. 브라우저에서 직접 Zen에 키를 보내는 경우에도 TLS 및 인증을 요구하고, 키가 클라이언트 응답이나 로그에 노출되지 않도록 해야 합니다.
- 저장 전 서버에서 검증하고, 배포 관리 키를 이용한 envelope encryption 또는 동등한 키 관리 체계로 암호화해야 합니다. 키 관리/회전/복구 설계가 없으면 저장 기능을 출시하지 않습니다.
- 일반 Web 사용자 API는 소유자별로 접근 통제하고, 키 평문은 저장 후 다시 읽어주지 않습니다. 관리형 Provider 자격 증명과 사용자 제공 키는 서로 분리합니다.
- 연결 테스트는 Provider 공식 API 규칙에 따르고, 짧은 timeout, 요청 제한 및 비밀정보 제거를 사용합니다. 제공자의 endpoint와 인증 방식을 확인하기 전에 임의 테스트 요청을 만들지 않습니다.
- 브라우저의 `localStorage`, URL, 쿠키의 비보호 필드, 저장되지 않는 메모리 외 지속 저장소에 서버용 비밀 키를 보관하지 않습니다.
- Provider 문서 확인 전에는 Provider를 “익명” 또는 “지원됨”이라고 표시하지 않습니다. `ck-`와 `xpi-`는 발급자와 인증 규격을 찾기 전까지 지원 자격 증명으로 취급하지 않습니다.
- 로컬 CLI의 개인 키 입력은 Web Zen 저장소와 별개의 기능이며, QraftCode 계정이 필수 조건이 되어서는 안 됩니다.

## 구현 순서

1. Provider 공식 문서/인증 요구사항 검증을 완료하고 해당 상태를 화면에 반영합니다.
2. Web 인증 및 사용자별 API 설정 API를 구현합니다.
3. 서버 자격 증명 암호화/키 관리와 비밀 정보 제거 테스트를 추가합니다.
4. 그 뒤에 설정 UI, 저장/삭제, 안전한 연결 테스트를 연결합니다.
5. 실제 Provider API에서 검증할 때만 해당 연결을 “확인됨”으로 표시합니다.

실제 backend와 보안 저장소가 구현되기 전까지 저장/연결 버튼은 동작하는 것처럼 표시하지 말고, 설정 화면을 제품 기능으로 간주하지 않습니다.
